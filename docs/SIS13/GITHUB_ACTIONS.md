# GitHub Actions protocol

The planning baseline `6645b5ef95e2cb4d00aa4bb6756705ac84475654` has no tracked `.github/workflows` files and GitHub returned zero Actions runs for that SHA. SIS13-15 owns proposing one shared, economical `pull_request` workflow against `main` in a scoped PR, with the baseline setup prepared alongside SIS13-14. Use repository-supported Python and Node versions, dependency lockfiles, least-privilege read permissions and deterministic fixtures. Install `backend/requirements.txt` plus required test tooling, run `python -m pytest backend/tests -q` at root, then `npm ci`, `npm run build`, and applicable mocked Playwright tests under `frontend/` (install Chromium with the runner dependencies). Use isolated fictional SQLite and mock or stub Groq. Keep optional live service smoke tests explicitly opt-in and outside default PR checks.

Add one incremental documentation/artifact validator if useful, for example `tools/sis13/validate_artifacts.py`. Validate artifacts present on a PR and require full presence only at final integration. Check E/I/A uniqueness, references, date window, rating columns/range/average, numerical baselines/targets, source paths, and readable image/PDF/PPTX artifacts. Limit costly jobs where safe while preserving visible PR check provenance. Publish logs and useful failure details. Keep teammate rating receipts and secrets out of artifacts.

Every task records commands and observed results appropriate to its outputs. Every PR records checked commit SHA, run URL, relevant job names, status and conclusion. Distinguish local outcomes from completed Actions jobs. State unavailable, pending or failed checks explicitly. Automated format checks prove structure and consistency; confirm permission, authenticity, usability and operational improvement by manual inspection.
