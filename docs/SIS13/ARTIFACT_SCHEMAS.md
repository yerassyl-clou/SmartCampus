# Artifact schemas and evidence

- Event register/timeline: event ID, exact local date, description, type, project effect, evidence IDs/links, strength (direct/corroborated/uncertain). Record original timestamp and Almaty date separately when needed. Build 8–15 distinct events and freeze IDs before rating. Sources may include consented team chat, ClickUp and GitHub. SIS13-01 owns the register and gives SIS13-05 the ordered roster without waiting for the graphic.
- Private rating template: Event ID | neutral label | integer rating −5 to +5 | optional context. Share one private copy per respondent before discussion. Ask each person to submit their own scores to Danaya privately. Use +5 very positive, 0 neutral, −5 very negative. With the team's agreement, use the stable codes below on the chart and keep the name key private. Clear identifiable publication rights before any GitHub commit. SIS13-05 can publish the method, code labels and approved values only. Retain genuine missing cells as empty.
- Canonical CSV header: `event_id,member_1,member_2,member_3,member_4,team_average`. Keep a private consistent member mapping. For each completed row calculate the sum of four integers divided by 4 and retain up to two decimal places. Leave the average blank for incomplete rows. Iterate through E-IDs in roster order. Report completion and rating provenance in the method, keep private notes out of the repo.
- Plot one line per participant and one mean line, events on X and −5…+5 on Y. Use visible differences in color and line styles. Call out extrema including ties, major adjacent changes and all events with a ≥4-point member spread. Cite optional volunteered context where permitted. Write 5–8 sentences of interpretation. Treat missing input as an evidence gap.
- Insight fields: I-ID, E-IDs, problem or successful practice, root cause with source, observed impact, proposed change and priority. Include supported seismograph observations. Write each successive why with evidence and mark uncertain links as hypotheses. Require ≥5 insights and use evidence, impact, urgency and feasibility to rank them.
- Action fields: A-ID, linked I-IDs, precise action, named owner, exact deadline, metric/unit, baseline, target, sampling/window and verification source. Pick ≥3 high-priority items. At least two must reach actual implementation. Capture matched baseline and after measurements using the same case, metric and denominator. Record baseline → target → measured actual, and use `partial` for an unfinished observation window with a checkpoint.
- Traceability: `E-xx → I-xx → A-xx → implementation → EV-xx → measured result`. Record evidence ID, description, capture date/time, task, related event/insight/action, source URL or path, verification method and before/after classification. Keep the actual baseline SHA, after SHA, environment, dataset, browser viewport, scenario and tool version where relevant. Use `sis13-07-a01-2026-11-24-before-chat-1440.png` as a naming example. Preserve originals, capture matching genuine before/after views, mask secrets or private fields and index annotations separately. Board changes require confirmed live configuration and before/after evidence. Historical screenshots and test totals retain their original dates.
- Place task outputs under `docs/SIS13/` in `event-timeline/`, `emotional-seismograph/`, `insight-backlog/`, `improvement-plan/`, `implementation/`, `quality/`, `report/`, or `presentation/` as named in the task. Use `evidence/{before,after,process,ux,ci}/` for authentic captures and logs. Place provenance in each task’s evidence index/record and link it from the implementation or source summary.
